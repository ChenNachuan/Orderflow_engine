## 一、`AffinityNodePool` —— 公司对象池（367 行）

### 1.1 三层架构
```text
GlobalArenaPool（进程级单例，一次性 mmap 16GB）
  └── AffinityNodePool（per-Side，从 arena 切 chunk）
        └── LIFO free list + bump pointer（per-node 分配/释放）
```

### 1.2 核心热路径（双热路径 + 零分支释放）
```cpp
T* allocate() {
    // 快路径 1：free list pop（1 次指针读）
    if (free_head_ != nullptr) {
        void* p = free_head_;
        free_head_ = *static_cast<void**>(p); // 已释放节点头 8 字节存 next 指针
        return static_cast<T*>(p);
    }
    // 快路径 2：bump pointer（顺序分配）
    if (cursor_ < end_) {
        char* p = cursor_;
        cursor_ += SLOT_SIZE;
        return reinterpret_cast<T*>(p);
    }
    // 冷路径：从 arena 切新 chunk
    return AllocateSlow();
}

void deallocate(T* ptr) {
    // 零分支：把释放节点头 8 字节写上 free_head_，然后更新 free_head_
    *reinterpret_cast<void**>(ptr) = free_head_;
    free_head_ = ptr;
}
```
- **对 M4 的精华**：① `free list` 复用释放节点的内存存 `next` 指针；② `bump pointer` 兜底保证连续性；③ `PrefetchNextAlloc()` 提前预取；④ 单票单日几十 MB 够用，无需 `GlobalArenaPool` 的 16GB 单例。

## 二、`BranchlessAssocVector` —— 无分支排序 vector（353 行）

核心使用 `conditional move`（`cmov`）替代条件分支做二分查找：
```cpp
const_iterator branchless_lower_bound(key_arg_type k) const {
    const auto* base = Base::data();
    size_type n = Base::size();
    while (n > 1) {
        size_type half = n / 2;
        // ★ 无分支：编译器生成 cmov 而非 branch
        base += static_cast<size_type>(MyCompare::operator()(base[half].first, k)) * half;
        n -= half;
    }
    if (n > 0 && MyCompare::operator()(base[0].first, k)) {
        ++base;
    }
    return begin() + (base - Base::data());
}
```
- **性能原理**：标准 `std::lower_bound` 每次 `if` 预测错误惩罚约 `~15 cycle`（128 个价位 7 次迭代可能浪费 `45~60 cycle`）；`cmov` 无预测惩罚，恒定 `~2 cycle`，总共仅 `~14 cycle`，且连续内存无 `std::map` 指针跳转的 cache miss。
- **落地节奏**：M1~M4 先用 `std::map` 保证正确性，M5 极致优化时再替换。

## 三、`SnapshotUpdater` —— 懒更新快照（220 行）

```cpp
// 每个 OnEvent 处理后：
void LazyUpdateSnapshot(e) {
    if (lazy_mode) {
        pending_update_ = true;                // 只标记有更新待刷
        cached_exch_time_ = GetExchangeTime(e); // 缓存时间戳
    } else {
        // 非 lazy 模式每次都刷
    }
}

// 外部调 GetSnapshot() 时：
void FlushSnapshot() {
    if (pending_update_) {
        UpdateExchangeTime(cached_time);
        FillSnapshot(output); // 真正刷新十档盘口
        pending_update_ = false;
    }
}
```
- **核心收益**：活跃股票日均几十万事件，按每 3 秒读一次快照只需刷 `~5000` 次，大幅减少十档遍历。
- **对 M3 的启发**：每 `3000ms` 调一次 `extract()` 本质上就是 lazy update；可额外在 `OrderBook` 内维护 `last_event_timestamp_`。

## 四、`OrderBookCommon` —— SSE/SZE 共用基类（394 行）

包含三大块：
1. **元数据**：`symbol`、`ii`、`price_factor`、`volume_factor`、`price_factor_inv`。
2. **状态机**：
   - `is_initialized_`（Init 后 true）
   - `started_`（收到首个事件后 true）
   - `in_batch_auction_`（开盘 true，09:30 切 false，14:57 切 true）
   - `is_good_`（`order not found` 等错误后变 false）
   - `ob_state_`（每次不一致 `IncState()++`，一致 `ResetState()=0`；`IsReady() = started_ && ob_state_ == 0`）
3. **四组件持有**：`data_`、`builder_`、`accessor_`、`emitter_`、`listener_caller_`。

### `IsPriceLevelGood` 检测 crossed book
```cpp
bool IsPriceLevelGood() const {
    return accessor_.trade_size() == 0 && // 没有 pending trade
           !(bid_num() > 0 && ask_num() > 0 &&
             GetBestBidPrice() >= GetBestAskPrice()); // 买一 < 卖一
}
```
- **设计优势**：用 `ob_state_` 计数而非简单 bool——偶尔一次 cross（如 pending trade 未处理完）后续可 `ResetState()` 恢复；连续多次 cross 累积则判定真有问题，快照标记不可信。
