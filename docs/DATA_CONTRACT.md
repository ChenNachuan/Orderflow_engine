# 数据契约与清洗规则

本文档定义 `Orderflow_engine` 与上游 Python 数据清洗层之间的输入契约，说明原始 A 股 L2 逐笔行情表的字段结构、沪深市场差异及事件归一化规则。

---

## 一、原始数据来源与基础约定

- **数据源**：QDC `cn_tick_l2` 历史 L2 数据，每个交易日每只标的包含三张原始 CSV 表：逐笔委托表、逐笔成交表、十档快照表。
- **文件编码**：`GB18030`。
- **价格精度**：原始字段为整型定点值，单位为 **万分之一元**（即实际元价格 × `10000`），清洗后原样以 `int64_t` 喂入引擎，不做浮点转换。
- **时间格式**：原始字段为 9 位整型 `HHMMSSmmm`（如 `93000000` 表示 `09:30:00.000`，常见精度为 10 毫秒），清洗时乘以 `10^6` 统一转换为纳秒整型 `uint64_t` 传入引擎。

---

## 二、原始三表字段说明

### 1. 逐笔委托表（10 列）

| 字段名 | 说明 | 处理策略 |
| :--- | :--- | :--- |
| 证券代码 | 标的代码 | 分表/分组键 |
| 交易所代码 | 沪市 / 深市标识 | 决定市场差异分支 |
| 自然日 | 交易日期 | 元数据 |
| 时间 | `HHMMSSmmm` | `× 10^6` 转为 `Event.timestamp` |
| 委托编号 | 深市历史冗余字段（恒为 0） | 忽略 |
| **交易所委托号** | 全局单调委托序列号 | **核心排序主键**，同时作为 `Event.seq` 与 `Event.order_id` |
| 委托类型 | `'0'` 限价、`'U'` 本方最优、`'1'` 市价等 | 决定价格转换与过滤逻辑 |
| 委托代码 | `'B'` 买入、`'S'` 卖出（部分含撤单标识） | 映射为 `Side::BUY` / `Side::SELL` 或沪市撤单 |
| 委托价格 | 万分之一元整数 | 映射为 `Event.price` |
| 委托数量 | 股数 | 映射为 `Event.volume` |

### 2. 逐笔成交表（12 列）

| 字段名 | 说明 | 处理策略 |
| :--- | :--- | :--- |
| 证券代码 / 交易所代码 / 自然日 | 标的与日期信息 | 元数据 |
| 时间 | `HHMMSSmmm` | `× 10^6` 转为 `Event.timestamp` |
| **成交编号** | 交易所成交序号（与委托号同源单调） | **核心排序主键**，作为 `Event.seq` |
| **成交代码** | `'0'` 普通成交、`'C'` 撤单（深市） | 区分 `EXECUTE` 与 `CANCEL` |
| 委托代码 / BS 标志 | 成交属性与主动方向 | 辅助信息（重建引擎以双边序号为准） |
| 成交价格 | 万分之一元整数 | 映射为 `Event.price` |
| 成交数量 | 成交股数 / 撤单股数 | 映射为 `Event.volume` |
| **卖序号** | 被成交或被撤的卖方委托号 | 若非 0，对应卖方 `Event.order_id` |
| **买序号** | 被成交或被撤的买方委托号 | 若非 0，对应买方 `Event.order_id` |

### 3. 十档快照表（66 列）

包含最新价、总成交量/额、以及买一至买十（价/量）、卖一至卖十（价/量）等 66 列切片数据。

- **用途 1（核心）**：作为黄金基准，在每个快照时点与引擎重建出的前 10 档盘口进行价量对拍验证。
- **用途 2（辅助）**：清洗层处理深市 `'U'`（本方最优）委托时，用于查询上一帧快照的最优买/卖价。该表**不直接作为事件喂入订单簿引擎**。

## 三、清洗归一规则（CSV → 统一 `Event` 流）

上游清洗脚本负责将原始三表规整为按单调序列号排列的统一 `Event` 流：

1. **逐笔委托表转换**
   - 常规限价委托（委托类型 `'0'`）：生成一条 `ADD` 事件，`seq` 与 `order_id` 均取自“交易所委托号”，方向取自 `'B'`/`'S'`。
   - 本方最优委托（委托类型 `'U'`）：在清洗阶段查找上一帧盘口的同侧最优价（买方取 `best_bid`，卖方取 `best_ask`）补全为限价后生成 `ADD` 事件；若当前同侧盘口无挂单，按异常边界丢弃或记录。
   - 市价单等极少数特殊委托：若无法确定有效挂单价格且非立即可成交剩余部分，当前阶段予以忽略。
2. **逐笔成交表转换**
   - **真成交（`成交代码 == '0'`）**：一条成交记录同时作用于买方与卖方挂单，拆分为**两条 `EXECUTE` 事件**——一条作用在 `买序号`（`Side::BUY`），另一条作用在 `卖序号`（`Side::SELL`），两者共享相同的 `timestamp`、`seq`、`price` 与 `volume`（要求对应序号非 0）。
   - **撤单（`成交代码 == 'C'`）**：取 `买序号` 与 `卖序号` 中非零的那个委托号作为目标 `order_id`，生成一条 `CANCEL` 事件。
3. **时间与序号归并**
   - 将委托流与转换后的成交/撤单流按交易所全局序号 `seq`（`ApplSeqNum`）进行 k-way 归并排序；同一 `seq` 下若存在同号拆分的双边 `EXECUTE`，保持确定性顺序输出，确保喂入引擎的事件流严格单调有序。

## 四、沪深市场差异处理

| 维度 | 深交所（SZE） | 上交所（SSE） |
| :--- | :--- | :--- |
| **撤单事件来源** | 在**逐笔成交表**中通过 `成交代码 == 'C'` 体现 | 在**逐笔委托表**中作为撤单记录（委托类型为撤单标识）体现，成交流仅含真实成交 |
| **事件乱序特性** | 按 `seq` 归并后基本严格有序 | 存在**成交早于委托到达**的乱序情况，依赖引擎 `pending_trades` 机制兜底 |
| **数据覆盖起始时间** | 完整覆盖逐笔委托与逐笔成交 | 逐笔委托数据自 **2021-07** 后才开始提供；此前历史区间无完整委托流，仅能基于快照计算因子 |
| **本方最优委托** | 存在 `'U'` 类委托，需结合上一帧盘口转限价 | 无需 `'U'` 转限价处理 |

## 五、交易时段与集合竞价处理规则

清洗层与引擎状态机按如下日内时间边界协同工作：

1. **开盘集合竞价申报（`09:15:00 – 09:25:00`）**
   - 保持 `in_batch_auction = true`，正常接收 `ADD` 与 `CANCEL`，此阶段买卖价格允许交叉，不视作异常。
2. **开盘集合竞价撮合（`09:25:00`）**
   - 集中撮合产生大量 `EXECUTE` 事件，剩余未成交挂单共同构成 `09:30` 开盘前订单簿的初始状态。
3. **连续竞价（`09:30:00 – 14:57:00`）**
   - 时间戳达到 `09:30:00.000` 时切换为 `in_batch_auction = false`，开启严格连续竞价盘口一致性校验（`best_bid < best_ask`）。
4. **收盘集合竞价（`14:57:00 – 15:00:00`）**
   - 深市 14:57 进入收盘集合竞价。当前版本采用简化策略：切换 `in_batch_auction = true`，跳过此区间订单簿重建或仅保留 14:57 前连续竞价的末态快照用于分钟特征输出。
