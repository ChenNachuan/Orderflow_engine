# 验证方案

本文档定义 `Orderflow_engine` 从底层数据结构到全市场还原的三级验证体系：核心单元测试矩阵、十档快照黄金基准对拍、特征值域不变量断言，以及首个最小手算验证序列。

---

## 一、单元测试矩阵（10 个核心场景）

针对 `PriceLevel` 链表维护与 `OrderBook` 事件处理，单元测试必须完整覆盖以下 10 个核心场景：

| # | 场景名 | 输入操作 | 预期状态与断言 |
| :--- | :--- | :--- | :--- |
| 1 | `SingleOrder` | 向买侧挂入 1 笔订单 | `best_bid` 等于该价格，`order_count == 1`，`head == tail == 该订单`，前后指针均为空 |
| 2 | `FrontOfQueue` | 同价位依次挂入 3 笔订单，检查队首状态 | `head` 为第 1 笔，`head->next` 为第 2 笔，其前序挂单量为 `0`，后序挂单量为第 2、3 笔之和 |
| 3 | `MiddleOfQueue` | 同价位依次挂入 3 笔订单，检查第 2 笔位置关系 | `order->prev` 为第 1 笔，`order->next` 为第 3 笔，前序量为第 1 笔，后序量为第 3 笔 |
| 4 | `BackOfQueue` | 同价位依次挂入 3 笔订单，检查队尾状态 | `tail` 为第 3 笔，`tail->next == nullptr`，前序量为前两笔之和，后序量为 `0` |
| 5 | `AskSide` | 向卖侧不同价格挂入多笔订单 | `best_ask` 取**最低**卖价，确认 `asks` 升序排序方向未写反 |
| 6 | `MultiplePriceLevels` | 买侧挂入两个不同价位（如 `10.00` 与 `9.99`），撤销其中一个价位的订单 | 另一价位的 `total_volume`、`order_count` 与链表结构完全不受串扰影响；空价位被正确移除 |
| 7 | `AfterCancel` | 同价位 3 笔订单中分别测试撤队首、撤队中、撤队尾 | 被撤节点 `prev`/`next`/`level` 清零，`head`/`tail` 正确推进或回退，剩余两笔直接相连且总量准确 |
| 8 | `AfterPartialExecute` | 对 500 股订单先后执行 200 股、300 股成交 | 首次成交后剩余 300 股且仍留在原排队位置、`order_count` 不变；第二次扣净后自动从价位与索引移除，若价位变空则删除价位 |
| 9 | `PendingTrade` | 先收到某 `order_id` 的 `EXECUTE`（200 股），再收到同 `order_id` 的 `ADD`（500 股） | 首次成交暂存至 `pending_trades`；委托到达时自动扣减为 300 股入簿；若提前成交量等于委托量则直接抵消不入簿 |
| 10 | `OrderNotFound` | 对不存在的 `order_id` 发送 `CANCEL` 事件 | 不崩溃、不污染已有价位，订单簿异常标志 `is_good` 置为 `false` |

## 二、十档快照对拍验证（核心端到端基准）

单元测试通过后，以真实历史数据中的**十档快照表**作为黄金基准进行全天流式回放对拍：

1. **对齐方式**：将逐笔事件流按时间推进至每一个快照时点（注意同毫秒时间边界的事件归属一致性）。
2. **比对内容**：对比引擎重建出的 `bids` 前 10 档（`bid_price_1..10`、`bid_vol_1..10`）与 `asks` 前 10 档（`ask_price_1..10`、`ask_vol_1..10`）与原始十档快照表是否一致。
3. **判定标准**：
   - 连续竞价时段（`09:30–14:57`）核心标的十档价量完全吻合，视为订单簿引擎重建逻辑正确；
   - 对出现偏差的样本，重点排查特殊委托类型（`'U'` 本方最优、市价单）、开盘集合竞价边界以及 `pending_trades` 乱序边界。

## 三、特征值域不变量断言

在回放全天或生成分钟因子时，对 `BookSnapshot` 批量执行结构性断言（仅针对双边非空且 `is_good == true && ob_state == 0` 的连续竞价正常快照）：

- `imbalance_1`、`imbalance_5`、`imbalance_10` 均落在 `[-1.0, 1.0]` 区间内；
- `spread >= 0`；
- 所有 `depth` 与 `levels` 均 `>= 0`，且满足单调非减：`depth_1 <= depth_5 <= depth_10`；
- 满足价格序关系：`bid_vwap_5 <= best_bid < best_ask <= ask_vwap_5`。

## 四、最小手算序列（首个可运行测试基准）

下表给出 5 条连续事件的最小手算 LOB 状态演变，可直接用作 `OrderBook` 建成后的第一个集成测试基准（价格已按 `×10000` 表示）：

| 步骤 | 事件输入 | 操作说明 | 操作后期望 LOB 状态 |
| :--- | :--- | :--- | :--- |
| 1 | `ADD`, `id=1`, `BUY`, `price=100000`, `vol=300` | 买一价 `10.00` 入队首 | `best_bid=100000`（总量 `300`，`1` 笔），`best_ask=无` |
| 2 | `ADD`, `id=2`, `BUY`, `price=100000`, `vol=500` | 同价位追加至队尾 | `best_bid=100000`（总量 `800`，`2` 笔，队列 `id=1 -> id=2`） |
| 3 | `ADD`, `id=3`, `SELL`, `price=100200`, `vol=400` | 卖一价 `10.02` 挂单 | `best_bid=100000`（`800`），`best_ask=100200`（`400`），`spread=200` |
| 4 | `EXECUTE`, `id=1`, `BUY`, `price=100000`, `vol=100` | 买一队首部分成交 `100` | `id=1` 剩余 `200`；`best_bid=100000`（总量 `700`，`2` 笔，队列仍为 `id=1 -> id=2`） |
| 5 | `CANCEL`, `id=1`, `BUY`, `price=100000`, `vol=200` | 买一队首剩余 `200` 全部撤单 | `id=1` 移除，`id=2` 升为队首；`best_bid=100000`（总量 `500`，`1` 笔），`best_ask=100200`（`400`） |
